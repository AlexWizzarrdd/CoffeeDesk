1. Регистрация и авторизация
---------------------------

### 1.1 Регистрация пользователя
POST /api/auth/register/

Тело запроса:
{
  "email": "test@mail.com",
  "password": "123456789",
  "first_name": "Иван",
  "last_name": "Иванов",
  "phone": "+79991234567"
}

Ответ:
{
  "id": 7,
  "email": "test@mail.com",
  "first_name": "Иван",
  "last_name": "Иванов",
  "phone": "+79991234567",
  "role": "employee",
  "is_approved": false,
  "is_active": false
}

Логика:
• Пользователь не может войти, пока менеджер не подтвердит аккаунт.
• is_active=false блокирует вход.
• Фронт должен показать сообщение:
  "Ваша учётная запись ожидает подтверждения менеджером".


### 1.2 Авторизация (логин по телефону)
POST /api/auth/login/

Тело запроса:
{
  "phone": "+79995550000",
  "password": "123456789"
}

Ответ:
{
  "refresh": "...",
  "access": "..."
}

Фронт должен:
• сохранить токены (localStorage.access и localStorage.refresh)
• сделать redirect в личный кабинет /profile


### 1.3 Личный кабинет
GET /api/auth/me/

Ответ:
{
  "id": 5,
  "email": "test@mail.com",
  "first_name": "Иван",
  "last_name": "Иванов",
  "phone": "+79995550000",
  "role": "manager",
  "is_approved": true,
  "is_staff": true
}

Правила:
• если токена нет → redirect на /login
• если сервер отвечает 401 → попробовать обновить токен или разлогинить


2. Управление пользователями (доступно manager и admin)
------------------------------------------------------

### 2.1 Список всех пользователей
GET /api/manager/users/

Ответ (пример):
[
  {
    "id": 1,
    "email": "test@example.com",
    "first_name": "Иван",
    "last_name": "Тестов",
    "phone": "+79990000000",
    "role": "employee",
    "is_approved": false,
    "is_active": false
  }
]

Фронт:
• вывод таблицы пользователей
• если is_approved=false → кнопка «Подтвердить»
• иначе → статус «Подтверждён»


### 2.2 Подтвердить пользователя
PATCH /api/manager/users/<id>/approve/

Запрос:
{
  "is_approved": true,
  "is_active": true
}

Ответ:
{
  "id": 1,
  "is_approved": true,
  "role": "employee"
}

Фронт:
• обновить таблицу после подтверждения


### 2.3 Удаление пользователя
DELETE /api/auth/users/<id>/delete/

Правила:
• пользователь не может удалить сам себя
• менеджер не может удалить менеджеров и админов
• админ может удалить всех


3. Роли пользователей
---------------------

Роль       | Описание
-----------|----------------------------------------------
employee   | обычный сотрудник
manager    | может подтверждать и видеть пользователей
admin      | как manager + может менять роли

Фронт:
• роль сохраняется после GET /me/
• UI скрывает/показывает функции в зависимости от роли


4. Работа с токенами JWT
-------------------------

Хранение:
• access → localStorage.access
• refresh → localStorage.refresh

Каждый запрос требует:
Authorization: Bearer <access>

Если access устарел → запрос обновления:
POST /api/auth/token/refresh/

Если refresh устарел → logout


5. Logout
---------

POST /api/auth/logout/

Тело запроса:
{
  "refresh": "<refresh_token>"
}

Ответ:
{
  "detail": "Logout successful"
}

Фронт:
• удалить оба токена
• redirect /login


6. Страницы фронтенда
---------------------

### /login
• телефон
• пароль
• кнопка «Войти»

### /register
• email
• телефон
• пароль

• фамилия

После регистрации:
“Ожидайте подтверждения менеджером”
